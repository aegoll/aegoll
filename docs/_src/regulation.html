Where the obligations fall

Every framework named here attaches its duties to a kind of entity: a licensed issuer, a registered service provider, an obliged institution. Tesoro is a library. It is none of those things, it cannot become one, and this page exists so nobody has to guess which parts of that are being claimed.

Why state this at all, rather than say nothing? Because silence in this area reads as a claim. A governance library that lists regulations without saying who they bind invites the reading that installing it addresses them — and that reading is wrong in a way that only becomes visible during an examination. Saying plainly what this is not is both safer for a reader and more useful than a page of logos.

Who each one binds

FrameworkBindsWhere this sits
GENIUS Act (US) Permitted payment stablecoin issuers — federal or state-qualified entities Outside. A library is not an issuer and cannot be permitted
MiCA (EU) EMT and ART issuers, and crypto-asset service providers Outside. Not an issuer, not a CASP
FATF R.16 (Travel Rule) Ordering and beneficiary institutions; VASPs for virtual-asset transfers Outside. It defines a record and never a message — see below
FCA (UK) · MAS (SG) · HKMA (HK) · VARA (AE) Licensed and registered firms in each jurisdiction Outside. Licensing is organisational; software is not licensable

The entity carries the obligation, always. If you are one of those entities and an agent spends through you, the exposure is yours — and it arrives without a category, because an autonomous agent is not an obliged entity under any of the seven. That is correct rather than an oversight: an agent has no legal personality and cannot hold a licence.

What was read, and what was not. The dates above come from the Federal Register listing and from published law-firm analyses, cross-checked against each other on 28 August 2026. The NPRM itself was not read in full. The FATF material elsewhere on this site was read in the source text — the consolidated Recommendations 2012–2025 and the June 2025 explanatory note — and that difference is stated rather than smoothed over.

One line in the April proposal is worth reading carefully

The FinCEN and OFAC proposal asks permitted issuers for the technical capability to block, freeze and reject specific transactions. That is a requirement about mechanism, not only about policy, and it points the same way this project does: toward controls that act before a transfer settles rather than reports that describe it afterwards.

It is still not a requirement this software satisfies. The obligation is on the issuer. What a library can offer is a place for that capability to be exercised and evidenced: Governor.freeze() refuses everything and says why, persisted, attributed to killswitch, and an unreadable state file reads as frozen rather than as permission. The sanctions control is the highest-precedence dispositive control, so a real screening provider has somewhere to land — and no engine sits behind it today.

What is not claimed, in plain terms

Not compliance

With GENIUS, MiCA, the Travel Rule, or any framework named on this site. None is claimed or sought, and no configuration of this software produces it.

Not AML screening

No list, no matching, no jurisdiction model. The stablecoin-1 profile requires an AML position in the record and this implementation does not conform to it.

Not Travel Rule support

It defines a record, never a transfer. Transmitting those fields, or presenting their presence as satisfying an obligation, is forbidden by the standard itself.

Not audited

Every conformance case and adversarial attack was written by the author of the system under test. That is a real limitation and it is not fixable by more of the same work.

What an obliged entity actually gets

Evidence, not compliance — and the distinction is the whole design. For a spend that an agent proposed, a record that answers: which accountable human authority it acted under, which control permitted or refused it, and how the transfer was initiated — the last being a fact R.16's required data set has no field for, because every element there identifies whose money moved and none identifies who instructed the movement.

Whether that evidence helps discharge any particular obligation is a legal determination requiring a qualified person, a jurisdiction and facts a technical layer does not hold. This software does not make that determination and neither does this page.
